# Контекст проекта

## Назначение продукта

`swipe_api` — backend MVP приложения знакомств. Проект больше не развивается как самостоятельный стартап; целевой результат — стабильная, понятная и самостоятельно разворачиваемая white-label кодовая база для демонстрации и дальнейшей разработки покупателем.

## Целевой демонстрационный сценарий

1. Регистрация пользователя по номеру телефона без обязательного доступа к реальному SMS-провайдеру.
2. Заполнение профиля и атрибутов.
3. Загрузка фотографии профиля без обязательных реальных S3/Firebase-ключей в demo-окружении.
4. Получение подходящих анкет.
5. Like или pass (в текущем API pass представлен dislike).
6. Обнаружение взаимного match.
7. Создание чата.
8. Обмен текстовыми Socket.IO-сообщениями.
9. Демонстрация подписки без реального платёжного списания.

Demo-путь должен запускаться локально, быть воспроизводимым и не требовать настоящих ключей SMSC, Firebase, Yandex Object Storage/S3, DaData или Т-Банка.

## Обязательный объём

- локальный запуск и управляемая схема PostgreSQL;
- регистрация/авторизация по телефону;
- профиль, атрибуты, интересы, геолокация и фотографии;
- выдача анкет и фильтры;
- like, dislike/pass, избранное и взаимный match;
- создание/получение чатов;
- текстовые сообщения и их статусы через Socket.IO;
- безопасный demo-режим для внешних интеграций и подписки;
- совместимость основного API с мобильным Flutter-клиентом;
- автоматические тесты основного demo-пути;
- документация запуска и передачи проекта покупателю.

## Исключённые функции

Без отдельной задачи не добавляются: настоящий AI matching, видеозвонки, голосовые сообщения, сложная модерация, новая административная панель, Kubernetes, высоконагруженная архитектура, настоящие рекуррентные платежи, новые внешние сервисы и крупный архитектурный редизайн. Уже существующий код этих направлений сохраняется.

## Архитектурные компоненты

- `main_app` — основной FastAPI HTTP API, порт 1024. Контроллеры: auth, user/profile, interests, likes, subscriptions, matches, communication, service/uploads, attributes.
- `socket_app` — FastAPI + python-socketio ASGI-сервис чатов и событий, порт 1025; хранит подключённые сессии в памяти и использует Redis pub/sub.
- `push_app` — FastAPI-обёртка Firebase Cloud Messaging, порт 1026.
- `admin_app` — отдельный FastAPI admin API, порт 1027.
- `common/models` — SQLAlchemy-модели PostgreSQL.
- `common/schemas` — общие Pydantic-схемы.
- `common/utils` — auth/JWT, CRUD, платежи/подписки, SMSC, push/socket helpers, scheduler и matching helpers.
- `config.py` — общая конфигурация, sync/async SQLAlchemy engines, Redis, Socket.IO и S3 client; создаёт большинство объектов при импорте.
- `alembic` — управляемые миграции БД.
- `docker-compose.yml` — Redis и четыре приложения; PostgreSQL в Compose отсутствует.

## Внешние интеграции

- PostgreSQL через `psycopg2`/`asyncpg` и SQLAlchemy;
- Redis для pub/sub событий верификации;
- SMSC.ru для SMS-кодов;
- Firebase Admin SDK для push;
- Yandex Object Storage через S3 API (`boto3`) для медиа;
- DaData (переменные и зависимость присутствуют; фактическое использование в проверенных путях не подтверждено);
- Т-Банк/Tinkoff acquiring (`Init`, `GetState`, `Charge`, webhook);
- Telegram verify-chat параметры;
- внешний mockapi endpoint для добавления случайных аватаров;
- OpenAI импортирован в helper matching, сетевой вызов закомментирован.

Текущее состояние этих интеграций не является demo-безопасным: единого конфигурационного переключателя demo/production и набора локальных адаптеров нет.
